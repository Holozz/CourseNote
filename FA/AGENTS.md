## 规范与读取范围

1. 以用户当前及本会话已明确的要求为准，再结合本文件、父目录规范和 skill 执行。
2. 开始笔记任务时，读取父目录 `../AGENTS.md` 和 `../index.md`；按任务需要查看 `../log.md`、`../LLM Wiki.md` 等仓库级规范文件。`../CLAUDE.md` 与父级 `AGENTS.md` 是硬链接，内容相同，无需重复读取。
3. 生成笔记必须使用 `obsidian-notes` skill：读取 `SKILL.md`，笔记撰写时读取 `references/note-authoring.md`，维护索引与日志时读取 `references/vault-maintenance.md`。具体文件格式的处理 skill 按需使用。
4. 每次只读取该任务指定的课件文件或章节范围。若只给了章节或主题，可以先查看默认课件目录的文件名以定位；不要批量打开、提取或摄入无关课件。多个候选无法可靠区分时，先澄清材料范围。
5. 可以按需读取本项目已有的同类笔记，参考结构、讲解深度、术语、符号和章节衔接；不需要遍历全部笔记。
6. 不浏览或读取父目录下其他学科文件夹的内容。父目录索引中的其他学科条目不构成读取那些笔记的授权。用户已授权本次参考 `../ML/AGENTS.md` 来建立本规范；后续任务无需再次读取 ML 目录。
7. 已有笔记是风格参考，课件是内容依据；已有笔记与父级规范或 skill 不一致时，遵循当前规范。不要借一次章节任务批量整改其他笔记。

## 笔记产出约定

- 新建章节笔记沿用本项目 `ChN 主题.md` 命名习惯，如 `Ch1 DFA.md`；需要时保留英文主题名。同一章已有文件则在原文件上更新，不另建重复版本。
- 本项目已有 `Ch1 DFA.md` 和 `Lecture_1_DFA.md`。任务涉及第 1 章时，优先遵循用户指定的目标；未指定时先判断两篇笔记的定位，不能确定则澄清，不自动合并、删除或再建第三份。
- frontmatter 使用父级规定的 `tags`、`课程`、`章节`、`教材` 字段；课程填写「形式语言与自动机」。未提供教材信息时留空，不臆造来源。不要照搬旧笔记中的 `title`、`aliases` 等额外字段。
- 按 skill 组织章节定位、目录、正文、例题、易错点速查和知识点速查；目录锚点与正文标题对应。
- 中文写作，中英文及数字之间加空格；使用 Obsidian Wiki-link、callout 和 LaTeX 数学公式，代码块标注语言。
- 覆盖指定材料范围内的全部知识点。讲清直觉、严谨定义、推导、证明和适用条件；公式说明符号，构造题说明设计思路，例题附详细解析。
- 自动机相关内容明确状态含义、字母表、转移规则、初态和接受条件；涉及空串、空语言、非确定性或 ε 转移时明确相应约定。证明区分充分性与必要性，语言相等须论证双向包含或给出完整的等价论证。
- 补充解释、推导和自拟例题应与课件原有内容区分；不把补充内容伪称为课件结论。无法辨认的图表或公式应明确标记，不猜写。
- 章节衔接优先链接本项目相关笔记，确认链接目标存在。
- 原始课件和已有 `Source/` 资料只读，不修改、重命名或删除。新增提取图片按章节命名，避免覆盖已有附件，使用 `![[图片名.png]]` 嵌入。

## 索引、日志与交付

- 新增或修改笔记后，按父级规范和 skill 同步维护 vault 根目录的 `index.md` 与 `log.md`。
- 索引学科分区名以现有写法为准。建立本规范时，父级索引尚无 FA 分区；后续笔记任务中若仍缺失，补建「FA — 形式语言与自动机」分区，并核对本项目应纳入索引的已有笔记，避免漏项。
- 只修改本任务相关条目、分区计数及必要的全局元信息；不扫描其他学科目录来重算总数。新增 FA 分区时同步补充「涵盖学科」，条目建议使用 `[[FA/文件名]]`。
- 日志保留历史，只增加本次操作记录；日期采用用户本地日期。
- `AGENTS.md` 属于规范文件，不计入课程笔记数量，不作为课程笔记条目加入索引。仅建立或修改本规范，不触发课程笔记的索引回填。
- 交付前检查课件覆盖、目录锚点、公式、内部链接、图片引用和索引日志同步情况；最终说明产出文件及仍未解决的材料问题。
