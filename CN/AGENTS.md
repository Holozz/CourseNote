## 规范与读取范围

1. 以用户当前及本会话已明确的要求为准，再结合本文件、父目录规范和 skill 执行。
2. 开始笔记任务时，读取父目录 `../AGENTS.md` 和 `../index.md`；按任务需要查看 `../log.md`、`../LLM Wiki.md` 等仓库级规范文件。父目录 `CLAUDE.md` 与 `AGENTS.md` 是硬链接，无需重复读取。
3. 生成笔记必须使用 `obsidian-notes` skill（用户所称的 obsidian-note）：读取 `SKILL.md`，笔记撰写时读取 `references/note-authoring.md`，维护索引与日志时读取 `references/vault-maintenance.md`。处理 PDF、PPTX 等材料时，按需使用对应格式的 skill。
4. 每次只读取该任务指定的课件文件或章节范围。若只给了章节或主题，可以先查看默认课件目录的文件名以定位；不要批量打开、提取或摄入无关课件。多个候选无法可靠区分时，先澄清材料范围。
5. 可以按需读取 CN 已有同类笔记的代表段落，参考结构、讲解深度、术语、符号、例题与章节衔接，不需要遍历全部笔记。
6. 不浏览或读取其他学科文件夹的内容。此次建规时用户明确授权参考 `../ML/AGENTS.md`；后续任务不因此获得读取 ML 笔记或其他学科内容的授权。父目录索引中的其他学科条目也不构成读取授权。
7. 已有笔记是风格参考，指定课件是内容依据；参考笔记中的错误或过时约定不沿用，不借一次章节任务批量整改其他笔记。

## 笔记产出约定

- 沿用本项目 `ChN 主题.md` 命名习惯，例如 `Ch1 简介.md`、`Ch2 应用层.md`、`Ch3 传输层.md`。同一章已有文件则在原文件上更新，不另建重复版本。
- frontmatter 使用父级规定的 `tags`、`课程`、`章节`、`教材` 字段；课程填写「计算机网络」。教材信息以指定材料为准，无法确认时留空，不臆造版本或来源。
- 通用骨架、写作与排版要求以 `obsidian-notes` 的对应 reference 为准，避免在本文件复制维护整套模板。
- 覆盖指定材料范围内的全部知识点，包括图表、证明、附录和习题承载的内容；先说明要解决的问题，再引入必要概念、定义、推导与适用条件。
- 协议讲解交代参与实体、报文、状态与触发条件；计算题说明符号、单位和假设，展开关键步骤，使读者能够复算。例题附详细解析，不只列出公式和答案。
- 补充解释、推导和自拟例题与课件原有内容区分；无法辨认的图表或公式明确标记，不猜写。
- 中文写作，中英文及数字之间加空格；使用 Obsidian Wiki-link、callout 和 LaTeX 数学公式，代码块标注语言。章节衔接优先链接本项目相关笔记，确认目标存在。
- 原始课件及已有 `Source/` 资料只读，不修改、重命名或删除。新增提取图片按章节命名，避免覆盖已有附件，使用 `![[图片名.png]]` 嵌入。

## 索引、日志与交付

- 新增或修改课程笔记后，按父级规范和 skill 同步维护 vault 根目录的 `index.md` 与 `log.md`。
- 索引使用现有「CN — 计算机网络」分区；只修改本任务相关条目、分区计数及必要的全局元信息，不扫描其他学科目录重算总数。
- 作业、实验报告、`Source/`、归档及规范文件不作为课程笔记纳入索引；依据内容用途判断，避免把 `Hw` 等作业文件误作课程笔记。既有无关条目的问题不在章节任务中顺手整改。
- 日志保留历史，只追加本次操作记录；日期采用用户本地日期，条目前缀按 skill 使用 `## [日期] ingest | 描述`。
- 本文件属于项目规范，不计入课程笔记数量，不作为课程笔记条目加入索引；仅修改规范时不触发课程笔记计数变化。
- 交付前检查指定材料覆盖、目录锚点、公式与计算、内部链接、图片引用及索引日志同步情况。静态检查与实际 Obsidian 界面渲染分开说明，不将未做的检查写成已完成。
- 若权限限制阻止父级索引或日志更新，按工具权限流程处理，并如实报告同步状态，不把未完成的更新写成已完成。
