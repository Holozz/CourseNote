## 一、实验目的

1. 掌握路由器接口 IP 地址的配置方法，区分直连路由与静态路由
2. 在两台路由器上配置到非直连网段的静态路由，实现两台 PC 跨网段通信
3. 使用接口状态、路由表和 ping 检查网络配置，对比静态路由配置前后的连通性
4. 处理实际接口与手册不一致、双网卡环境下主机选路等问题

## 二、实验环境与网络拓扑

### 1. 实验环境

本次实验使用第 13 组实验室设备，包括两台 Windows 计算机和两台华为路由器 R1、R2，使用终端通过 Telnet 管理路由器

计算机保留校园网与设备管理所用的网卡，另一块网卡用于实验网络，R1、R2 的管理地址分别为 `172.16.13.203/16` 和 `172.16.13.204/16`

实际设备使用 GigabitEthernet 接口，R1 的 GE0/0/1 连接 PC1，GE0/0/2 连接 R2；R2 的 GE0/0/5 连接 PC2，GE0/0/6 连接 R1，配置时按实际接口编号操作

### 2. 网络拓扑

实验划分为三个网段，PC1 与 R1 之间为 `192.168.1.0/24`，R1 与 R2 之间为 `192.168.2.0/24`，R2 与 PC2 之间为 `192.168.3.0/24`

![[src/拓扑图.png]]

实际地址与接线如下：

| 设备 | 接口 | IP 地址 | 子网掩码 | 默认网关或连接对象 |
| --- | --- | --- | --- | --- |
| PC1 | 实验网卡 | 192.168.1.11 | 255.255.255.0 | 默认网关 192.168.1.1 |
| R1 | GE0/0/1 | 192.168.1.1 | 255.255.255.0 | PC1 |
| R1 | GE0/0/2 | 192.168.2.1 | 255.255.255.0 | R2 的 GE0/0/6 |
| R2 | GE0/0/6 | 192.168.2.2 | 255.255.255.0 | R1 的 GE0/0/2 |
| R2 | GE0/0/5 | 192.168.3.1 | 255.255.255.0 | PC2 |
| PC2 | 实验网卡 | 192.168.3.22 | 255.255.255.0 | 默认网关 192.168.3.1 |

## 三、实验步骤与结果

### 1. 配置两台 PC 的实验网卡

在 Windows 中运行 `ncpa.cpl`，进入实验网卡的 IPv4 属性，设置 IP 地址、子网掩码和默认网关

PC1 配置为

```text
IP 地址：192.168.1.11
子网掩码：255.255.255.0
默认网关：192.168.1.1
```

PC2 配置为

```text
IP 地址：192.168.3.22
子网掩码：255.255.255.0
默认网关：192.168.3.1
```

配置后执行 `ipconfig`，检查实验网卡地址，PC2 同时保留校园网网卡的 `172.16.13.2` 和默认网关 `172.16.0.1`

PC1 的地址检查结果

![[src/pc1配置.png]]

PC2 的地址设置及检查结果

![[src/pc2配置ip.jpg]]

### 2. 配置 R1 的接口地址

进入系统视图，将 R1 的两个实验接口分别配置到 PC1 网段和路由器互联段

```text
system-view
sysname R1
interface GigabitEthernet 0/0/1
ip address 192.168.1.1 24
undo shutdown
quit
interface GigabitEthernet 0/0/2
ip address 192.168.2.1 24
undo shutdown
quit
display ip interface brief
```

执行结果中，GE0/0/1 为 `192.168.1.1/24`，GE0/0/2 为 `192.168.2.1/24`，两个接口的 Physical 和 Protocol 均为 `up`

![[src/路由器r1配置完成.png]]

### 3. 核对并配置 R2 的实际接口

最初按手册尝试进入 Ethernet 接口，设备返回 `Unrecognized command`，改用 GigabitEthernet 后能够进入接口视图，相关报错及处理记录见第四部分

随后曾将 `192.168.3.1/24`、`192.168.2.2/24` 配置在 GE0/0/1、GE0/0/2 上，检查结果中两个接口均为 `down/down`，实际接 PC2 的 GE0/0/5 已有物理连接

![[src/pc2配置接口2完成.jpg]]

核对接线，将 R2 的 GE0/0/6 与 R1 的 GE0/0/2 相连，截图下半部分记录了 GE0/0/6 的物理状态变为 `up`，此时该口尚未配置 IP，协议状态仍为 `down`

![[src/pc2的6接口和pc1的2接口相连.jpg]]

在 R2 系统视图中，删除误配在 1、2 口上的实验 IP，再将地址配置到 5、6 口

```text
interface GigabitEthernet 0/0/1
undo ip address 192.168.3.1 24
quit
interface GigabitEthernet 0/0/2
undo ip address 192.168.2.2 24
quit
interface GigabitEthernet 0/0/5
ip address 192.168.3.1 24
undo shutdown
quit
interface GigabitEthernet 0/0/6
ip address 192.168.2.2 24
undo shutdown
quit
display ip interface brief
```

R2 最终使用 GE0/0/5 连接 PC2，GE0/0/6 连接 R1，后续路由表中的两条直连网段分别对应这两个接口

## 四、实验过程中遇到的问题及解决方法

### 1. 接口类型与指导手册不一致

在 R2 输入 `interface Ethernet0/0/1` 时，设备返回 `Unrecognized command found at '^' position`

通过以下命令检查设备支持的接口类型和已有接口

```text
display interface brief
interface ?
```

设备列出的接口类型为 GigabitEthernet，改用 `interface GigabitEthernet 0/0/1` 后进入接口视图，后续配置按实际接线选用 GE0/0/5、GE0/0/6

![[src/进入接口.jpg]]

### 2. 接口已启用，但配置地址的端口与接线不对应

执行 `undo shutdown` 时出现 `is not shutdown` 提示，该提示表示接口原本未被管理关闭，不属于配置失败

随后检查发现，已配置 IP 的 R2 GE0/0/1、GE0/0/2 均为 `down/down`，实际接线使用 GE0/0/5、GE0/0/6，按第三部分的命令删除误配地址并重新配置

接口的管理启用状态、物理连接状态和协议状态分别检查，不能仅凭 `is not shutdown` 判断链路已连通

### 3. 配置实验网关时提示多个默认网关

两个PC都保留了校园网网卡，以PC2为例，其默认网关为 `172.16.0.1`；为实验网卡填写 `192.168.3.1` 后，Windows 提示多个默认网关用于单一网络冗余，在两个分离网络上可能无法正常工作

本次保留管理网络以便访问设备，同时保存实验网卡配置，后续通过添加到实验目标网段的明确路由处理主机选路

### 4. PC1 可以 ping 通 PC2，PC2 主动访问 PC1 失败

配置两台路由器的静态路由后，PC1 能 ping 通 PC2，但 PC2 ping `192.168.1.11`、`192.168.1.1` 均超时，ping 本侧网关 `192.168.3.1` 收到四次回复；继续测试互联地址 `192.168.2.2`、`192.168.2.1` 也未收到回复

故障截图记录了 PC1 地址、R1 网关地址的失败结果，以及 PC2 本侧网关的成功结果

![[src/问题pc2ping不到pc1.jpg]]


ping了几次R1和PC1，都不通，怀疑并不是防火墙的问题，
可能是并没有发送到 PC1 实验网的网关；
随后在 PC2 以管理员身份打开 CMD，添加到 PC1 所在网段的路由，然后重新测试

```bat
route add 192.168.1.0 mask 255.255.255.0 192.168.3.1
ping 192.168.1.11
```

`route add` 返回“操作完成！”，随后收到来自 `192.168.1.11` 的四次回复，发送 4 个、接收 4 个、丢失 0 个，回复 TTL 为 `126`

![[src/修复问题.jpg]]

这条命令修改的是 PC2 的 Windows 路由表，使发往 `192.168.1.0/24` 的数据交给实验网关 `192.168.3.1`，与路由器上配置的两条静态路由分别承担主机出站选路和跨网段转发

说明数据必须先选对出口交给R2后面才能让R2、R1正确转发

## 五、实验思考题

### 1. 在配置静态路由前，PC1 ping PC2，分析此时为何不通

接口地址配置完成、相关接口正常工作后，R1 的实验直连网段为 `192.168.1.0/24`、`192.168.2.0/24`，R2 的实验直连网段为 `192.168.2.0/24`、`192.168.3.0/24`

PC1 访问 `192.168.3.22` 时，需要通过默认网关将数据交给 R1，R1 缺少到 `192.168.3.0/24` 的路由；PC2 的回复也需要经过 R2 返回 `192.168.1.0/24`，R2 同样缺少该网段的路由，在没有其他可用路由的实验起始状态下，两台 PC 无法完成通信

### 2. 要实现 PC1 和 PC2 的通信，本实验共配置了几条静态路由，分别是什么，其含义是什么

在两台路由器上共配置两条静态路由

```text
R1：ip route-static 192.168.3.0 24 192.168.2.2
R2：ip route-static 192.168.1.0 24 192.168.2.1
```

第一条将 R1 发往 PC2 网段的数据交给 R2，第二条将 R2 发往 PC1 网段的数据交给 R1，分别提供到远端网段的转发路径

后面实际操作的时候还在 PC2 上添加一条 Windows 静态路由，指定访问 `192.168.1.0/24` 时使用实验网关 `192.168.3.1`，用于修复配置静态路由后仍然 ping 不通的问题

### 3. 如果路由器中存在去往同一网段的多条路由信息，路由器会采用哪一个进行转发

转发时，对已安装的路由条目按最长前缀匹配选择，匹配的前缀越长，目的范围越具体

对于同一目的前缀的候选路由，优先比较路由优先级，数值越小越优先；优先级相同时，再比较相应路由机制下的开销，选择开销较小的路径，条件相同且设备支持时可以形成等价多路径

本次华为设备中的直连路由优先级为 `0`，静态路由优先级为 `60`；PC2 添加的 `/24` 主机侧路由优先于匹配所有目的地址的 `/0` 默认路由

## 六、实验总结

本次完成两台 PC 的地址配置、两台路由器的接口配置和双向静态路由配置，路由表中记录了对应的直连网段、下一跳与出接口

静态路由配置前，PC1 到 PC2 的四次 ping 请求超时；配置后，PC1 收到 PC2 的四次回复，丢包率为 0%；在 PC2 添加到 PC1 网段的主机侧静态路由后，反向测试也收到四次回复，丢包率为 0%

实验中处理了接口类型不一致、R2 端口与接线不对应、多默认网关提示及 PC2 主机选路问题，最终实现 PC1 与 PC2 跨路由器通信

通过本次实验，我们组进一步理解了静态路由通信的基本原理和实现方法，以及对路由选择问题的解决，掌握了配置静态路由的基本方法，加深了对PC之间跨网段通信的认识
