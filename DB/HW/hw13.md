## 1

### a. 每个关系存储在一个文件中
优点：
1. 管理简单：文件结构统一，插入、删除和扫描单个关系比较方便
2. 单表查询效率较高：文件中只包含该关系的记录，不需要跳过其他关系的数据
缺点：
3. 连接查询可能产生较多 I/O：相关关系存放在不同文件中，连接时需要分别读取多个文件
4. 相关记录物理距离较远：无法把经常一起访问的记录放在同一个磁盘块中
### b. 多个关系存储在一个文件中
优点：
1. 连接查询效率较高：可以把不同关系中相互关联的记录存放在同一个或相邻磁盘块中，减少 I/O。
2. 按关联对象查询更快：例如把一个院系记录和该院系的教师记录放在一起，查询某院系及其教师时可以集中读取。
缺点：
3. 单表扫描效率可能下降：只查询其中一个关系时，需要跳过文件中其他关系的记录。
4. 存储管理更复杂：不同关系的记录格式和长度可能不同，需要额外记录类型信息或维护指针链。
## 2

### a. 如果值为空
那么 Offset 可以置为 -1（约定为无效值），这时 length 为 0. 分别存储偏移量和长度
### b. 修改记录表示
可以取消对 NULL 元素的 Offset 和 length 的存储，通过 bit map 里指示 0 或 1 来判断当前元素是否为 NULL （也就是是否有这两个字段），这样一个 NULL 属性就只占用 bitmap 里的 1 bit

## 3

因为数据库是以 block 为基本单位执行的磁盘 I/O：
- 如果一次要查询的多条 record 存储在不同的 blcok 内，那就要分别执行磁盘 I/O，增加了次数
- 如果经常被一起扫描或者顺序扫描的 record 存储在不相邻、分散的 blcok 内，那就要比连续的分配增加了磁盘寻道和访问开销
- 如果 block 内存储的 record 过多或者过少，可能会出现新的 record 插入需要分配新的 block，或者是 block 内空间大量空闲造成存储浪费
## 4

因为数据库以 block 为单位对记录进行存储，当前只要目标块溢出了就得分配新的块
