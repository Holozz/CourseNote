# 二、简答题
1. 输出结果应该是 `child: x = 15\n  parent: x = 2`，因为父进程调用了 `wait(NULL)` 等待子进程的结束，子进程中 `x += 10` 得到15，父进程中 `x -= 3` 得到2
2. 
	共享内存：
		优点：
			可用于任意进程（如通过 mmap 或 System V 共享内存）；只在建立共享内存区域时需要内核介入，后续数据交换由进程直接读写内存，无需内核每次介入，性能高，延迟低；多个进程直接共享同一块物理内存区域，批量通信效率高
		缺点：
			同步复杂，必须使用互斥锁等机制；安全性差，一个进程的错误可能会破坏共享数据；局限于同一台物理主机的进程
	消息传递：
		优点：
			进程之间相互通信无需借助共享变量；安全性高，消息是拷贝传递，不会互相污染；跨平台，利用套接字等扩展到分布式系统；多核处理器中没有cache一致性的问题
		缺点：
			性能比较低，每次通信要利用系统调用，内核接入，并且拷贝数据，开销大；延迟高，消息排队、拷贝；不适合批量数据
	场景：在同一主机内的大数据量的高频传输使用共享内存；其余大部分情况，分布式系统，或者数据量不大，安全性要求高，跨网络通信等就使用消息传递
3. 
	 僵尸进程：已经终止，但是PCB还在系统中，等待父进程收集其推出状态的进程
		产生：也就是父进程不使用 `wait()` 等待，则其子进程就会成为僵尸进程
		操作系统会等待父进程调用 `wait()` 然后删除该进程，如果一直不调用，则僵尸进程会一直占用资源；如果父进程先一步终止，则僵尸进程会被自动回收
	孤儿进程：父进程已经终止但是自身还在运行的进程
		产生：父进程先于子进程结束
		操作系统的1号进程会收养孤儿进程，然后自动调用 `wait()` 回收

# 三、分析题
(a)原因： `in` 指向下一个可写入的位置， `out` 指向下一个可读取的位置，于是判断数组空的条件为 `in == out` ，判断数组满的条件为 `(in + 1) % BUFFER_SIZE == out` ，若数组大小为 `BUFFER_SIZE` ，就无法进行区分
(b)改进：增加一个计数器 `count` 变量记录当前缓冲区中的数据数量
```
#define BUFFER_SIZE 10
typedef struct {
    item buffer[BUFFER_SIZE];   // 共享缓冲区
    int in;                     // 写指针（下一个空位索引）
    int out;                    // 读指针（下一个待取数据索引）
    int count;                  // 当前缓冲区中的数据项数量
} buffer;
```
`count == 0` 即为空 `count == BUFFER_SIZE` 即为满
