# 概念
- 程序：一段代码
- 进程：正在执行的程序
	- 进程执行必须**按顺序**执行
	- 结构部分：
		- **程序代码**（文本段）
		- **当前活动**，包括==程序计数器、处理器寄存器==
		- 临时数据的**堆栈**，包含函数参数、返回地址、全局变量
		- 包含**全局变量**的数据部分
		- 包含在运行时**动态分配的内存**的堆
- 进程与程序：
	- 当一个可执行文件**加载到内存中**时，程序变成进程
	- 通过GUI、命令行等启动程序的执行
	- 一个程序可以是**多个**进程（多个用户执行同一个程序）

- 进程销毁：
	- 正常完成：进程自行执行一个操作系统服务调用，表示它已经结束运行。
	- 超过时限：进程运行时间超过规定的时限，可测量多种时间，如总运行时间、执行时间等。
	- 无可用内存：系统无法满足进程需要的内存空间。
	- 超出范围：进程试图访问不允许访问的内存单元 。
	- 保护错误：进程试图使用不允许的资源或文件，或使用方式不正确。
	- 算术错误：进程试图进行被禁止的计算，如除以零等。

	- 无效指令：进程试图执行不存在的指令。
	- 特权指令：进程试图使用为操作系统保留的指令。
	- 数据误用：错误类型或未初始化的数据。
	- 操作员或操作系统干涉：操作员或操作系统因某些原因终止进程。
	- 父进程终止：父进程终止时，系统可能自动终止其子进程。
	- 父进程请求：父进程有权终止其子进程
- 进程挂起
	- 挂起的进程的特征
	- 挂起原因
- 进程表：
	- 必须进行维护以管理进程
	- 必须直接或间接引用内存、IO和文件
	- 操作系统必须能够访问表本身，因此需要进行内存管理
	- 在操作系统初始化时就会创建进程表
- 进程控制块(PCB)
	- 是操作系统控制和协调各种活动进程所需要的信息
	- 包含**进程相关的信息或者进程的表示**：
		- 进程状态–正在运行、等待等。
		- 程序计数器–下一个执行指令的位置
		- CPU寄存器–所有以进程为中心的寄存器的内容
		- CPU调度信息-优先级、调度队列指针内存管理信息–分配给进程的内存
		- 记账信息–使用的CPU、启动后经过的时钟时间、时间限制
		- I/O状态信息–分配给进程的I/O设备、打开的文件列表
	- **作用**：
		- 是操作系统**最重要**的数据结构
		- 每个PCB都包含了操作系统所需进程的所有信息
		- 进程存在的**唯一标识**
		- 实现进程切换
		- 进程调度的基础
		- 资源管理与保护
		- 支持进程间的通信
# 调度
- Processor Scheduler从可用进程选择下一个在CPU核心上执行的进程
- 目标：最大限度利用CPU，快速将进程切换到CPU核心
- 维护进程的队列：
	- 就绪队列
	- 等待队列
	- 进程在各种队列之间迁移
- 进程切换的方式：
	- 中断：没有指向性
	- 系统调用：具有指向性
## 长期调度器（Long-term Scheduler）
### 1. 作用与时机
- **将磁盘上的新作业/进程**选中并调入内存，为其创建进程（分配 PCB 等资源）。
- 运行时机：一个作业刚提交到系统时，或者内存中有空闲空间允许接纳新进程时。
### 2. 控制多道程序度（Degree of Multiprogramming）
- **核心功能**：控制内存中同时存在的进程数量（即多道程序度）。
- 如果度太小，CPU 可能经常空闲；度太大，进程竞争内存、CPU 等资源，导致频繁交换或性能下降。
### 3. 执行频率
- **很低**：几秒甚至几分钟才执行一次（因为进程的创建和终止频率远低于 CPU 调度）。
- 长期调度器在批处理系统中非常重要；在现代分时或通用 OS（如 Linux、Windows）中，通常没有显式的长期调度器，而是由用户直接启动进程（“立即创建”），但内核仍隐式控制并发数（通过内存压力等）。
### 4. 选择策略
- 通常平衡 **I/O 密集型进程** 与 **CPU 密集型进程** 的比例。
- 如果过多 I/O 密集型进程 → 设备忙但 CPU 空闲；过多 CPU 密集型 → I/O 设备空闲。
- 经典批处理系统中，长期调度器会考虑作业的优先级、预估运行时间、资源需求等。
## 短期调度器（Short-term Scheduler）
### 1. 作用与时机
- **从就绪队列中选择一个进程**，将 CPU 分配给它（执行上下文切换）。
- 运行时机：时钟中断、I/O 完成、系统调用、进程主动放弃 CPU 等，频率极高。
### 2. 执行频率
- **很高**：通常每隔几十毫秒就可能执行一次（时间片到期），或者更频繁。
- 必须非常高效，因为它的开销会直接影响系统吞吐量。
### 3. 控制目标
- 追求 **CPU 利用率**、**响应时间**、**周转时间**、**公平性** 等。
- 常用算法：FCFS、SJF、优先级调度、轮转（RR）、多级队列/多级反馈队列等。
### 4. 特点
- 只能从内存中已存在的进程（即已进入就绪队列的进程）中选择，不能从磁盘调入新进程。
- 运行在内核态，常由时钟中断或系统调用触发。
## 两者主要区别总结

|维度|长期调度器|短期调度器|
|---|---|---|
|**执行频率**|很低（秒/分钟级）|很高（毫秒级）|
|**主要功能**|控制多道程序度，将进程从磁盘调入内存|从就绪队列选进程分配 CPU|
|**调度对象**|作业（磁盘上的程序）|进程（已驻留内存）|
|**影响系统性能的方面**|影响 I/O 与 CPU 进程混合比例、内存并发数|影响响应时间、吞吐量、CPU 利用率|
|**是否参与进程切换**|否，只在进程进入内存时工作|是，每次 CPU 切换时工作|
|**存在场景**|批处理系统明显；现代通用 OS 往往退化/简化|所有多道程序系统都存在|

## 补充：中期调度器（Medium-term Scheduler）
为了完整性，再提一下**中期调度器**（部分教材有介绍）：
- 负责**交换**（swapping）：将进程从内存移到外存（挂起状态），或从外存重新调入内存。
- 执行频率介于长期与短期之间。
- 主要目的：释放内存、调整多道程序度，尤其用于分时系统内存不足时。
## 常见误区澄清
- **错误**：长期调度器并非仅在微内核中存在；它主要存在于批处理系统，现代宏内核也可能有类似机制（如内存不足时抑制创建新进程）。
- **正确**：长期调度器控制多道程序度，执行频率远低于短期调度器。
- **错误**：短期调度器只从内存中的就绪队列选进程，**不负责从磁盘调入内存**（那是长期或中期调度器的职责）。
- **错误**：长期调度器并非只选 I/O 密集型进程；它会平衡 I/O 密集型和 CPU 密集型进程。

### **`wait()`**
- wait系统调用会暂停发起调用的父进程
- 当子进程从running转为terminated时，wait结束，会return并且唤醒发起调用的进程

## 进程的终止`exit()`
- 进程执行最后一条语句，然后调用`exit()`系统调用请求OS删除它
	- 通过`wait()`将状态信息返回到父进程
	- 进程的资源由OS释放
- 父进程可以使用`abort()`系统调用终止子进程
	- 子进程超出资源的分配
	- 不需要子进程的任务了
	- 父进程要退出
- 父进程终止，则不允许子进程存在，由OS启动
	- 父进程可以使用`wait()`系统调用等待子进程终止，并且返回终止的状态`pid = wait(&status)`
- 如果父进程不使用`wait()`那么子进程就是僵尸进程

### IPC
- IPC的两种模型
	![[Pasted image 20260401154050.png|500]]
- 共享内存
	- 通信双方需要同时映射共享内存到自己的进程中
	- 通信由用户进程控制，而不是OS
	- 主要问题是提供一种机制，允许用户进程在访问共享内存时同步其操作

- **错误**：共享内存可用于任意进程（如通过 mmap 或 System V 共享内存），不限于父子进程。

# IPC在共享存储系统中的应用
## IPC消息传递
- 进程之间相互通信，无需借助共享变量
- IPC两种操作：
	- Send
	- Receive
- 消息的大小是可变的或固定的
- 两个进程间的通信需要：
	- **建立通信链接**
	- 通过Send/Receive交换信息
- 问题：
	- 如何建立联系
	- 链接是否可以和两个以上的进程关联
	- 每对通信进程之间可以有多少链路
	- 链路的容量
	- 链接可以容纳的消息是固定还是可变
	- 链接是单向的还是双向的
## 通信链路的实现
- 物理：
	- 共享内存 
	- 硬件总线
	- 网络
- 逻辑：
	- 直接或间接
	- 同步或异步
	- 自动缓冲或显式缓冲
- 直接通信：
	- 进程之间必须明确命名：
		- 发送P：向P发送
		- 接收Q：从Q接收
	- 链路特点：
		- 自动建立
		- 链路仅与一对通信进程关联
		- 每对之间只存在一个链接
		- 可能单向，通常双向
	- **展示了寻址的对称性，即发送和接收进程必须指定对方**
	- 也可以采用非对称性，即只要发送者指定接收者
- 间接通信：
	- 通过邮箱或者端口来发送和接收消息
		- 邮箱有唯一的id
		- 进程只有在共享邮箱的时候才能通信
	- 链路特点：
		- 仅当进程共享邮箱时才建立连接
		- 连接可与多个进程关联
		- 每对进程可以共享多个链路
		- 单向或者双向
	- 操作：
		- 创建新邮箱
		- 发送接收邮件
		- 删除邮箱
	- 基本体定义为：
		- 发送A：发送到邮箱A
		- 接收A：从A接收消息
	- 邮箱共享：
		- P1、P2和P3共享邮箱A
		- P1发送，P2、P3接收
	- 解决方案：
		- 允许链接最多与两个进程相关联
		- 一次只允许一个进程执行接收操作
		- 允许系统任意选择接收器 通知发送方接收者是谁
	- 邮箱所有者：
		- 进程
		- 操作系统
		- 可以转移
## 同步
消息传递可以是阻塞的，也可以是非阻塞的
- 阻塞被认为是同步的
	- 阻塞发送——在接收进程或者邮箱收到消息之前，发送进程阻塞
	- Blocking receive——在消息可用之前，接收进程将被阻塞
- 非阻塞被认为是异步的
	- 非阻塞发送——发送进程发送消息并继续执行
	- 非阻塞接收——接收进程接收有效消息或空消息
	- **性能高于阻塞同步的通信**
- 可能有不同的组合：如果**发送和接收都是阻塞**的，双方之间有一个**交会**
- 生产者-消费者 （阻塞）消息传递
- 缓存
	- 附加到连接的消息队列，不管通信是直接还是间接
	- 以三种方式之一实现队列：
		1. 零容量——链路上没有消息排队。发送方必须等待接收方
		2. 有限容量——有限长度的n条消息，如果链路已满，则发送者必须等待
		3. 无限容量——无限长，发送方从不等待

## 管道（Pipe）
- 充当两个进程通信的管道
- 存在的问题：
	- 通信是单向还是双向
	- 在双向的情况下，是半双工还是全双工
	- 通信进程之间的关系
	- 这些管道是否可以通过网络使用，或者在本地
- **普通管道**：无法从创建它的进程外部访问。通常，父进程创建管道并使用它与它创建的子进程通信
- **命名管道**：可以在没有父子关系的情况下访问
### 普通管道
- 允许标准生产者消费者风格通信
- 生产者写入一段
- 使用者从另一端读取数据
- **单向**
- 需要通信进程之间的父子关系
- Windows调用这些匿名管道
### 匿名管道
- 在Windows系统中普通的管道称为匿名管道
- 与Unix的普通管道类似
- 单向、父子进程之间传输
### 命名管道
-  比普通管道功能更强大
- 双向
- 通信进程之间不需要父子关系
- 有几个进程可以使用命名管道进行通信
- 在Unix和Windows上都提供
## 客户机-服务器系统中的通信
- 套接字（Socket）
- 远程过程调用（RPC）
- 套接字被定义为通信的端点
- IP地址和端口的串联-包含在消息包开头的数字，用于区分主机上的网络服务
- 通信由一对套接字组成
### 套接字
### 远程过程调用
- 远程过程调用（RPC）抽象网络系统上进程之间的过程调用
	- 再次使用端口进行服务区分
- Stubs–服务器上实际过程的客户端代理
- 客户端存根定位服务器并封送参数
- 服务器端存根接收此消息，解压缩封送的参数，并在服务器上执行该过程
- 在Windows上，存根代码根据用Microsoft接口定义语言（MIDL）编写的规范编译
