## 二、简答题
1. 临界区
	临界区是多线程/多进程环境中，访问共享资源（如共享内存、文件、数据结构）的那段代码。同时刻只允许一个线程进入临界区执行，否则会产生竞态条件（race condition）。
	临界区问题的三个基本要求：
	1. 互斥
		同一时刻最多只有一个进程/线程在临界区内执行。如果进程 A 正在临界区中，其他任何进程都不能进入。
    2. 前进
		如果没有进程在临界区中，且有进程希望进入，那么只有不在剩余区的进程可以参与决定谁进入临界区，且这个选择不能被无限期推迟。通俗讲：想进的人里必须选一个出来，不能让大家都等着而没人进去。
	3. 有界等待
		  一个进程从提出进入请求到实际进入之间，其他进程进入临界区的次数有上限。这保证不会出现"饥饿"——某个进程一直在等，而其他进程反复插队。
2. 
	- ”关中断“只影响当前 CPU 核的中断标志位，其他核上的线程仍然可以同时访问共享资源。在单核上关中断能阻止上下文切换从而保证原子性；在多核上，核 A 关了中断，核 B照样跑，两者仍然可以同时进入临界区——互斥完全失效。
	- 与硬件原子指令的对比：关中断是是在内核态下仅对当前CPU核（不保证多核互斥）的所有中断的操作；硬件原子指令可以内核态或者用户态，对所有核（保证多核互斥）仅目标缓存行的操作，不影响其他操作
3. 
	- 二值信号量 vs 计数信号量：二元信号量的取值范围是0和1，主要用于实现互斥锁；计数信号量的取值范围是非负整数，主要用来管理多个同类资源实例
	- wait(S) / signal(S) 缺少原子性的后果：两个进程都能进入临界区，信号量的互斥作用失效；并且信号量的值也会错乱，因为两个进程都在操作计数；导致不可预测的行为
4. 
	- 读写器锁：一种区分读写操作的同步机制，允许多个读者同时访问，但是只允许一个写者同时访问
	- 当多线程程序只使用读写器锁进行同步时，若存在多个读写器锁，是可能发生死锁的：对写入者来说，资源不能共享，可以导致互斥；线程持有某锁的同时等待另一把锁；并且锁也不能被抢走，是不可抢占的；线程之间形成等待环也会出现循环等待。比如两个线程各有一个写锁，并试图获取对方的写锁
5. 
	- 安全状态：系统存在至少一个安全序列，可以让所有进程都顺利完成
	- 不安全状态：不存在任何可能的安全序列，无法保证所有进程都能完成，但是不等于死锁
	- 死锁状态：一组进程中，所有进程都在等待只能被其他进程释放的资源，导致所有进程都不能释放，也不能获取资源，永久阻塞
	- 死锁条件：互斥；持有并等待；不可抢占；循环等待
## 三、分析题
1. 
	(a) `flag[]` 用于表示进程是否想进入； `turn` 表示现在轮到哪个进程
	(b) 
		- 互斥：若两个进程都执行完 `turn = other` 后，`turn` 只能是最后赋值的那个值。假设 P0 和 P1 都想进入，最后 `turn = 0`（P1 设置），则 P1 的 while 条件 `turn==0 && interested[0]==TRUE` 为真，P1 等待；P0 的条件 `turn==1` 为假，P0 进入
		- 推进若 P1 不想进入（`interested[1]=FALSE`），P0 的 while 条件立即为假，P0 直接进入
		- 有限等待：P1 离开后设 `interested[1]=FALSE`，P0 的 while 条件为假，P0 最多等一次
	(c) Peterson 算法在顺序一致性下是正确的，但现代多处理器大多采用弱内存模型，如果没有内存重排序，导致为了追求性能可能会乱序执行语句，那么对 `flag` 和 `turn` 的读取也可能被乱序执行或被提前预测，这样可能导致互斥被破坏或者提前进入临界区；如果没有内存屏障强制刷新，那么两个kernel可能会各自写各自的存储缓冲区，导致彼此读取的值不是最新的。
2.  由于南北车辆逻辑是一样的，这里就只给出南向
	```cpp
	semaphore bridge    = 1   //桥的状态
	mutex south_mutex       //锁
	int south_count = 0     //当前在桥上的南行车辆数
	
	void south_enter():
	    lock(south_mutex)
	        south_count++
	        if south_count == 1:       //第一辆南行车
	            wait(bridge)           //抢占桥
	    unlock(south_mutex)
	
	void cross_bridge(int direction){...}
	
	void south_exit():
	    lock(south_mutex)
	        south_count--
	        if south_count == 0:       //最后一辆南行车
	            signal(bridge)         //释放桥
	    unlock(south_mutex)
	```
	当任一方向的车进入后，比如南向，那么已经执行了 `south_enter()` ，那么肯定有第一辆南向车的进入，这辆车会执行 `wait(bridge)` 使得其值从1变为0，那么这时候就不应该有另外方向的桥来抢占，否则其值将要变为-1除非其一开始的值是2，但是 `bridge` 是二值信号量，所以不可能会出现反向车辆
