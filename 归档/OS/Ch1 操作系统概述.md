## 操作系统
### 操作系统目标
- **方便用户**：执行用户程序，使用户解决问题更容易
- **使计算机系统更易用**：协调程序运行，确保系统高效工作
- **更有效地使用计算机硬件**：分配各种资源，提高系统利用率
## Cache大小和块大小
Cache大小：小空间cache对系统性能的影响非常明显
块大小：cache与主存进行交换的单位

## 指令执行
一个程序包含一组指令集合，并且存储在内存中；
基本的指令周期：2处理器从内存读取指令，PC+1--->执行指令
通过循环保持一直运行


## 对称多处理器（SMP）

### 特征
- 两个或两个以上具有**同等能力**的相似处理器
- 处理器**共享相同的主存储器**，并通过总线或其他内部连接方案互连
- 处理器**共享对I/O设备的访问**
- 所有处理器都可以执行相同的功能
- 系统由**集成操作系统控制**，该系统在作业、任务、文件和数据元素级别提供处理器及其程序之间的交互
### 优势
- Performance
- Availability
- Incremental Growth
- Scaling

## 非统一内存访问（NUMA）
有些NUMA结构的CPU不知道自己专属的memory，会访问到其他CPU的专属memory导致效率变低

# 操作系统执行
## 操作系统的执行
1. **引导程序(Bootstrap Program)** - 初始化系统、加载内核的简单代码，一般位于==只读存储器(ROM)或可编程只读存储器(EEPROM)
2. 内核加载
3. 启动系统守护进程（在内核之外提供的服务）
4. 内核中断驱动（硬件和软件）
	- 其中设备的硬件中断
	- 软件中断（异常或陷阱）
		- 软件错误
		- 操作系统服务请求-系统调用
		- 故障处理
## 多道程序设计（批处理）
- 单用户不能总是让CPU和IO设备忙碌
- 多道程序设计组织作业，所以CPU总是有一个作业要执行
- 系统中所有作业的一个子集保存在内存中
- 选择一个作业通过作业调度运行
- 当作业必须等待时，系统切换到另一个作业
## 多任务（分时）
批处理系统的逻辑扩展–CPU频繁切换作业，用户可以在作业运行时与作业交互，从而创建交互式计算;
- 响应时间应该小于1s
- 每个用户至少有一个程序在内存中执行过程
- 如果多个作业就绪同时运行进程调度
- 如果进程不适合内存，交换程序将他们移入和移出 内存
- 虚拟内存允许执行不完全在内存中的进程
## 双模式操作
- 双模式操作允许操作系统保护自身和其他系统组件
	- 用户模式和内核模式![[Pasted image 20260309090231.png]]
	- 区别：内核模式下CPU可执行**特权指令**，==只能在内核模式运行==（如I/O操作、中断管理），并能访问**所有内存空间**；用户模式下只能执行非特权指令，且只能访问**用户空间**。这种隔离防止用户程序破坏系统或干扰其他进程，是实现**安全保护**的基础。
- 由硬件提供的**模式位**
	- 提供区分系统何时允许用户代码或内核代码的能力
	- 当用户正在运行时模式位 *1* 为“用户”
	- 当内核代码正在执行时模式位 *0* 为“内核”
- 如何保证**用户不显式地将模式位设置为“内核”？
	- 通过系统调用将模式更改为内核，从调用返回将其重置为用户
- **特权指令**：如设定定时器的值、清除内存、管理中断操作、修改设备状态表的条目、有关I/O操作
- **非特权指令**：如读取时钟、产生陷阱、用户态切换到内核态

- 当操作系统引导时，硬件从内核模式开始；
- 操作系统被装载后，开始用户模式下执行用户程序；
- 一旦出现中断或者陷阱，硬件从用户模式切换到内核模式；
- 当操作系统能够控制计算机时，处于内核模式；控制权交给用户程序前，系统切换到用户模式；
**当切换模态时，资源消耗非常大**，因此有的系统会把两个模态合一。![[Pasted image 20260309091226.png]]

## 系统调用
通过**中断/trap**完成系统调用
- System calls are the programming interface between processes and the OS kernel
	- System calls provide the means for a user program to ask the operating system to perform tasks
- A system call usually takes the form of a trap to a specific location in the interrupt vector, treated by the hardware as a software interrupt
- The system call service routine is a part of the OS
## 多重模式执行
- 两模式扩展到多模式，典型：虚拟化
- 支持虚拟化基数的CPU有一种单独模式，用于表示虚拟机管理器VMM
	- 这种模式的特权大于用户，小于内核
### 虚拟化
- 允许操作系统在其他操作系统中允许应用程序
	- 云计算
- 当源CPU类型不同于目标类型时使用的仿真
	- 很慢
	- 要把本机的语言翻译为虚拟机的语言
- 操作系统为CPU本机编译，运行Guest操作系统也为本机编译
- 用例涉及多个操作系统的笔电和台式机，以便于探索或兼容
	- 运行Mac OS X主机、Windows作为Guest的苹果笔记本电脑
	- 在没有多个系统的情况下为多个操作系统开发应用程序
	- 无需多个系统的质量保证测试应用程序
	- 在数据中心内执行和管理计算环境；
## 定时器
- 防止无限循环
	- 定时器设置为在一段时间后中断计算机；
	- 保留一个由物理时钟递减的计数器；
	- 操作系统设置计数器（**特权指令**）；
	- 当计数器为零时，产生一个中断；
	- 在调度进程之前设置，以重新控制或终止超出分配时间的程序；
## 进程管理
*进程*是正在执行的程序。是系统中的一个工作单元，是操作系统**分配资源的最小单位**（调度的最小单位是线程）。
- 进程的每个线程都有一个程序计数器（PC）
- 进程需要资源来完成其任务
	- CPU、内存、I/O、文件
	- 初始化数据
- 进程终止需要回收任何可重用资源
- 系统上有许多进程，一些 用户，一些操作系统在一个或多个CPU上并发运行

操作系统负责与进程管理相关的以下活动：
- 创建和删除用户和系统进程
- 暂停和恢复进程
- 提供进程同步机制
- 为进程通信提供机制
- 提供死锁处理机制
