# 线程
- 线程是CPU调度的基本单元
- 线程只包含运行时的状态
	- 静态部分由进程提供
	- 包括了执行所需的最小状态
- 一个进程可以包含多个线程
	- 每个线程共享同一地址空间，包含代码段、数据段和其他操作系统资源
	- 允许进程内并行
- 线程包含**线程ID**、**程序计数器**、**寄存器组**、**堆栈**
- 
- 一个进程的多线程可以在不同处理器上同时执行
	- 调度的基本单元由进程变为线程
	- 每个线程都有状态
	- 上下文切换的单位变为了线程
- 每个线程有自己的栈
- 内核中有为线程准备的内核栈
	- 内核的线程绑定在操作系统内核的进程
## 动机
一个服务器接收到请求时，它会创建另一个进程来处理请求，但似乎进程的创建很耗时间和资源，所以如果新进程和原进程执行同样的任务，可以创建一个单独线程来完成

## 多线程的优点
- 响应性：如果部分线程被阻塞，仍可以继续执行
- 资源共享：线程之间的共享进程资源比进程共享内存更容易，允许一个应用程序在统一地址空间内有多个不同的活跃进程
- 经济：比进程创建更便宜

# 线程库
- 线程库为程序员提供了创建和管理线程的API;
- 两种主要的实施方式:
	- 第一种方式：在用户空间中提供一个没有内核支持的库；
	- 第二种方法是实现操作系统支持的内核级库；
- 三种主要的线程库：
	- POSIX Pthreads （用户层次或者内核层次）
	- Windows （内核层次）；
	- Java （利用windows API或者Pthreads来实现）；
- 创建多线程的方法
	- 异步：一旦父线程创建子线程之后，父线程就恢复自身的执行。这样父子线程就会并发执行，两个线程独立。独立的线程之间很少有数据共享
	- 同步：创建子线程之后会等待所有子线程的终止。只有在所有子线程都终止并与父线程连接之后，父线程才恢复执行
## Pthreads
- 可以作为用户级或内核级提供
- 用于线程创建和同步的POSIX标准（IEEE 1003.1c）API 规范，而不是实现；
- API指定了线程库的行为，实现取决于库的开发；
- 在UNIX操作系统（Linux和Mac OS X）中常见
- 与进程的方法对比：![[Pasted image 20260415143350.png|400]]
### pthread_create()
```c
	void * hello( void *input ) {
		 printf(“%s\n”, (char *) input);
		 pthread_exit(NULL);
	}
	
	int main(void) {
		 pthread_t tid;
		 pthread_create(&tid, NULL, hello, “hello world”); "Hello线程创建，和main一起执行"
		 pthread_join(tid, NULL); "和进程中wait()类似，目标线程的终止会使该函数返回"
		 return 0;
	}
```
- 一个线程是从一个特定的函数（线程函数）开始的

## 线程池
- 在池中创建多个线程，在其中等待工作
- 优势：
	- 比创建新线程快一点

	- 将要执行的任务和创建任务的机制分离，可以使用不同的策略来运行任务

## 信号处理
- 在UNIX系统中，信号用于通知进程某个特定事件已发生。
- 信号处理器用于处理信号
	1. 信号由特定事件产生
	2. 信号被传送到进程
	3. 信号由两个信号处理程序之一处理：
		（1）缺省的信号处理程序；
		（2）用户定义的信号处理程序；
- 每个信号都有内核在处理信号时运行的默认处理程序
	- 用户定义的信号处理程序可以覆盖默认值
	- 对于单线程，信号传输到进程
- 多线程的信号应该在哪里传递？
	- 将信号传递到应用该信号的线程
	- 将信号传递给进程中的每个线程
	- 将信号传递给进程中的某些线程
	- 指定一个特定线程来接收进程的所有信号
## 线程终止
- 在线程结束之前终止它
- 要终止的线程称为目标线程
- 两种方法：
	- 异步终止立即终止目标线程
	- 延迟终止允许目标线程定期检查是否应该终止
- Pthread用于创建和终止线程的代码
- 调用线程请求终止，但实际终止取决于线程状态
- 若线程已禁用终止，则终止将保持挂起状态，直到线程启用它为止
- 默认类型是延迟的
	- 终止仅在线程到达终止点时发生（系统调用常用终止点）
		- 例如，pthread_testcancel（） 然后调用清理处理程序
- 在Linux系统上，线程终止是通过信号处理的
