## 1. 存储分层体系

现代计算机的存储从快到慢、从贵到便宜形成层次结构：

```
寄存器 → 高速缓存(Cache) → 主存(DRAM) → 固态硬盘(SSD) → 机械硬盘(HDD) → 磁带/光盘
  ↑速度快、容量小、价格贵                           速度慢、容量大、价格便宜↑
```

操作系统的存储管理覆盖三层：

- **文件系统实现层**：FAT32、EXT2/3、KV存储、分布式文件系统等
- **设备层**：磁盘、SSD 等物理存储设备
- **用户空间**：进程通过文件系统操作访问数据

## 2. 磁盘（HDD）工作机制

### 2.1 物理结构

机械硬盘是一种"机械+电子"的复合设备，理解其物理结构是理解性能瓶颈的基础。

|术语|含义|
|---|---|
|**盘片（Platter）**|圆形磁性介质，数据存储在表面；一块硬盘有多个盘片叠在一起|
|**磁道（Track）**|盘片上的同心圆，每个盘片有多条磁道，编号从外到内|
|**扇区（Sector）**|磁道上的最小存储单元，通常 512B（历史）或 4KB（现代）|
|**柱面（Cylinder）**|所有盘片上**相同编号磁道**的集合（形成圆柱形）|
|**磁头（Head）**|每个盘片表面对应一个磁头，负责读写；所有磁头连在同一个磁臂上，**同时移动**|

> [!warning] 易错点：柱面 vs 磁道
> 
> - 磁道是单个盘片上的圆圈
> - 柱面是所有盘片上**位置对应**的磁道集合
> - 访问同一柱面的不同磁道**不需要移动磁臂**，只需切换磁头（速度很快）

### 2.2 访问时间构成

磁盘每次 I/O 的时间由三部分构成：

$$T_{访问} = T_{寻道} + T_{旋转延迟} + T_{数据传输}$$

**① 寻道时间（Seek Time）**

- 磁臂从当前位置移动到**目标磁道**所需时间
- 这是最慢的部分，通常 3ms ~ 12ms
- 台式机 HDD 平均约 9ms
- **磁盘调度算法主要就是优化这一项！**

**② 旋转延迟（Rotational Latency）**

- 磁盘转到目标扇区到达磁头位置所需时间
- 公式：平均旋转延迟 = 转一圈时间 / 2
- 7200 RPM 的硬盘：转一圈 = 60/7200 ≈ 8.33ms，平均延迟 ≈ **4.17ms**
- 10000 RPM：平均延迟 ≈ 3ms

**③ 数据传输时间（Transfer Time）**

- 数据从磁盘传到内存的时间，通常很短（相对前两者）
- 理论传输速率 6Gb/s，实际约 1Gb/s

> [!example] 计算例题 **题目**：7200 RPM 硬盘，平均寻道时间 5ms，传输速率 1Gb/s，控制器开销 0.1ms。传输一个 4KB 数据块的平均 I/O 时间是多少？
> 
> **解**：
> 
> - 平均旋转延迟 = 60/7200/2 × 1000ms = **4.17ms**
> - 数据传输时间 = 4KB / 1Gb/s = (4 × 8 × 1024 bit) / (10^9 bit/s) ≈ **0.031ms**
> - **总时间 = 5 + 4.17 + 0.1 + 0.031 ≈ 9.30ms**
> 
> 注意：即使传输只有 4KB，寻道+旋转就占了约 99.7% 的时间！这就是为什么减少寻道次数如此重要。

## 3. NVM（非易失性内存）与 SSD（solid-state disks）

### 3.1 NVM 概述

NVM（Non-Volatile Memory）是没有机械运动的存储设备，断电不丢数据：

- **固态硬盘（SSD）**：最常见的 NVM 应用，外形像磁盘
- **USB 闪存盘、手机存储**：也是 NVM
- **DRAM 磁盘**：用 DRAM 模拟磁盘，速度极快但断电丢数据（易失性）

### 3.2 SSD 的优势

|指标|HDD|SSD|
|---|---|---|
|寻道时间|3~12ms|**0**（无机械部件）|
|旋转延迟|2~6ms|**0**|
|随机 IOPS|数百|数十万|
|顺序读写速度|~200MB/s|**>500MB/s**|
|抗震性|差|**好**|
|功耗|高|**低**|
|价格/GB|低|高|

### 3.3 SSD 的工作原理

SSD 基于 **NAND Flash** 闪存：

- 通过高压改变浮栅晶体管（floating-gate transistor）的状态来存储数据
- 晶体管状态被解释为二进制数据（0/1）
- 多颗 Flash 芯片**条带化（RAID）**以提高吞吐量

### 3.4 SSD 的挑战

> [!danger] 重难点：写放大（Write Amplification）

**Flash 的读写单位不对称**：

- **写（Program）**：以**页（Page）** 为单位，4~16 KB
- **擦（Erase）**：以**块（Block）** 为单位，128~256 KB（包含多个页）

**问题根源**：Flash 不能直接覆盖写，必须先擦除整个块，再写入。

- 如果块中部分页是有效数据、部分是旧数据（stale），就必须：
    1. 把有效页读出来
    2. 擦除整个块
    3. 把有效页写回
    4. 再写入新数据
- 这就导致一次逻辑写触发**多次物理读+擦+写**，即"**写放大**"

```
逻辑写 1次  →  物理操作 多次（读有效页 + 擦块 + 写回 + 写新数据）
```

**磨损均衡（Wear Leveling）**：

- 每个 Flash 单元只能写 3000~5000 次（MLC）
- SSD 控制器通过**磨损均衡**将写操作分散到所有单元，延长寿命

### 3.5 垃圾回收（GC）与 TRIM

**问题**：大多数文件系统删除文件只是移除元数据（如 Linux 的 `unlink()`），不通知 SSD 哪些页已失效。SSD 以为所有页都有效，GC 时白白复制无用数据。

**解决方案 —— TRIM 命令**：

- SATA 的 TRIM 命令（SCSI 中称 UNMAP）
- 允许 OS 明确告诉 SSD：某些 LBA 已经无效，可以被 GC
- OS 支持：Windows 7、macOS Snow Leopard、Linux 2.6.33+、Android 4.3+
- **同时需要 SSD 固件支持**

> [!warning] 易错点 TRIM 不是"真删除数据"，而是告知 SSD"这些页不再需要了"，方便 GC 清理，从而保持写入性能。

### 3.6 SSD 控制器

SSD 内部有专用控制器，负责：

- **LBA → 物理页的映射**（Flash Translation Layer, FTL）
- 跟踪空闲页，控制 GC 时机
- 后台 GC（Background GC）
- 磨损均衡（Wear Leveling）

控制器性能直接决定 SSD 整体性能。

## 4. 磁盘与主机连接

### 4.1 接口总线

|接口|特点|
|---|---|
|**SATA**|最常见的 HDD/SSD 接口|
|**eSATA**|SATA 的外部版本|
|**SAS**|企业级，Serial Attached SCSI|
|**USB**|通用，外置设备|
|**NVMe（PCIe）**|**NVM 专用接口**，直连 PCIe 总线，速度远超 SATA|

> [!tip] NVMe 为什么快？ 传统 SSD 通过 SATA 接口通信，SATA 协议是为 HDD 设计的，有延迟和带宽限制。NVMe 协议专为 Flash 设计，**直连 CPU 的 PCIe 总线**，延迟极低、带宽极高。

### 4.2 控制器架构

- **主机控制器（Host Controller / HBA）**：主机端，位于主板上
- **设备控制器（Disk Controller）**：磁盘驱动器内置的
- 主机通过**内存映射 I/O 端口**向主机控制器发命令
- 计算机使用内存映射的I/O端口将命令放置在主机控制器上
	- 主机控制器向设备控制器发消息
	- 数据通过 **DMA（直接内存访问）** 在设备和 DRAM 之间传输

### 4.3 地址映射（LBA）

磁盘对外暴露的是**逻辑块地址（LBA，Logical Block Address）**，即一维编号的块数组：

- **LBA 0** = 最外层柱面第一磁道第一扇区
- 从外到内，按磁道、柱面顺序递增编号
- 低级格式化（物理格式化）在物理介质上创建逻辑块，逻辑块通常比物理内存块大一点

> [!warning] 逻辑到物理映射的难点
> 
> - 坏扇区存在时需要跳过，映射变复杂
> - 以恒定角速度（CAV）访问时，外圈磁道比内圈长，每条磁道扇区数可能不同

## 5. 磁盘调度算法

> [!info] 为什么需要调度？ 磁盘调度的核心目标：**最小化总寻道时间**（磁臂移动到目标扇区柱面的时间 ），从而提高吞吐量。 

**示例环境**：200 磁道（0-199），磁头初始位置：**100** **请求队列**（按到达顺序）：**55, 58, 39, 18, 90, 160, 150, 38, 184**
- 磁盘I/O请求的来源：
	- 操作系统
	- 系统进程
	- 用户进程
- I/O请求包括输入或输出模式、磁盘地址、内存地址、要传输的扇区数
- 操作系统维护每个磁盘或设备的请求队列
- 空闲磁盘可以立即处理I/O请求，繁忙磁盘意味着工作必须排队。只有当队列中有多个待处理请求时，调度算法才有意义。
### 5.1 FIFO（先来先服务）

**策略**：按请求到达顺序依次服务。
**轨迹**：100 → 55 → 58 → 39 → 18 → 90 → 160 → 150 → 38 → 184
**总移动距离** = |100-55|+|55-58|+|58-39|+|39-18|+|18-90|+|90-160|+|160-150|+|150-38|+|38-184| = 45+3+19+21+72+70+10+112+146 = **498 道**

**优点**：
- 最公平，每个请求都会被处理
- 不会产生饥饿

**缺点**：
- 若有大量进程竞争磁盘，性能趋近于随机调度
- 总移动距离大，效率低

---
### 5.2 SSTF（最短寻道时间优先）

**策略**：每次选择离当前磁头**最近**的请求（贪心算法）。

**轨迹**：100 → 90 → 58 → 55 → 39 → 38 → 18 → 150 → 160 → 184

**总移动距离** = 10+32+3+16+1+20+132+10+24 = **248 道**（约为 FIFO 的一半）

**优点**：

- 总移动距离显著减少，吞吐量高
- 小队列情况下表现极好

**缺点**：

- **可能导致饥饿**：如果磁头附近持续有新请求，远端的请求永远得不到服务
- 不公平

> [!warning] 易错点：SSTF ≠ 最优 SSTF 是贪心算法，并不保证全局最优移动距离。它每步选局部最优，可能错过更优的全局方案。

---

### 5.3 SCAN（扫描算法 / 电梯算法）

**策略**：磁头像电梯一样，**来回移动**。在某一方向上服务所有请求，到达最末磁道后**反向**继续服务。

**轨迹**（假设初始向高磁道方向）：100 → 150 → 160 → 184 → **199（端点）** → 90 → 58 → 55 → 39 → 38 → 18
**总移动距离** = (199-100) + (199-18) = 99 + 181 = **280 道**

**优点**：
- 比 FIFO 效率高，比 SSTF 更公平
- 不容易饥饿（最终每个磁道都会被扫描到）

**缺点**：
- 对**靠近两端**的磁道有偏好（经过端点时才服务）
- 刚被扫过的区域要等将近一整圈才能再次被服务

> [!tip] 改进版：LOOK 算法 SCAN 会移动到磁盘物理末端（如第 199 道）再折返，即使那里没有请求。 **LOOK** 的改进：只移动到**最后一个有请求的磁道**，然后折返。更高效，实际实现中常用 LOOK 而非 SCAN。

---

### 5.4 C-SCAN（循环扫描）

**策略**：只在**一个方向**扫描。到达末端后，**快速返回起点**（不服务返回途中的请求），然后再次向同一方向扫描。

**优点**：
- 对所有磁道提供**更均匀**的等待时间
- 减少服务时间的方差（variance）

**缺点**：
- 返程不服务，浪费了一些移动时间

> [!tip] 改进版：C-LOOK 算法 类似 LOOK 对 SCAN 的改进：返回时只回到**有请求的最小磁道**，而不是物理起点 0。

---

### 5.5 N-step-SCAN 与 FSCAN

**N-step-SCAN**：

- 将请求队列分成长度为 N 的子队列
- 每次处理一个子队列（用 SCAN），处理期间新请求加入其他子队列
- 防止磁头因局部请求集中而"卡住"

**FSCAN**：

- 使用两个子队列（N-step-SCAN 的特例）
- 扫描开始时，所有请求在队列A，队列B为空
- 扫描过程中新请求加入队列B
- 队列A处理完后，切换到队列B扫描
- **服务保证更强，彻底消除了扫描过程中的"插队"现象**

---

### 5.6 算法对比总结

|算法|总移动距离（示例）|公平性|饥饿|适用场景|
|---|---|---|---|---|
|FIFO|498（最差）|最好|无|请求少、负载轻|
|SSTF|248（较好）|差|**有**|吞吐量优先|
|SCAN|280|中|基本无|负载较大|
|C-SCAN|稍多于SCAN|最均匀|基本无|高负载、低方差|
|N-step-SCAN|介于SCAN|中|无|服务保证|
|FSCAN|类似SCAN|中|无|负载敏感|

> [!important] 选择调度算法的原则
> 
> - **SSTF** 最常见，有天然吸引力（贪心直觉）
> - **SCAN/C-SCAN** 对磁盘负载较大的系统更好，减少饥饿
> - **Linux Deadline 调度器**：
> 		- 维护读/写两个队列，读优先（因为进程更可能在读时阻塞，写时有互斥保护）
> 		- 实现四个队列（2读+2写），一对按 LBA 顺序（C-SCAN），一对按 FCFS 顺序，防止超时请求被长期忽视

---

### 5.7 NVM 的调度

SSD 没有磁头和旋转延迟，因此：

- 传统调度算法意义不大
- Linux RHEL 7 对 NVM 使用 **NOOP**（无调度），但会合并相邻 LBA 请求
	- NVM 的最佳场景是**随机 I/O**（HDD 最佳是顺序 I/O）
	- 使用NVM时，每秒输入/输出操作数（IOPS）要高得多（几十万比几百）
	- 写放大问题会削弱 NVM 的性能优势

## 6. 错误检测与纠正

|机制|说明|
|---|---|
|**奇偶校验位**|最简单的错误检测，只能检测奇数位错误，不能纠正|
|**CRC（循环冗余校验）**|使用哈希函数检测多位错误，常见于网络传输|
|**ECC（纠错码）**|既能检测又能纠正部分错误|

- **软错误**（soft error）：可被 ECC 纠正
- **硬错误**（hard error）：ECC 能检测到但无法纠正

## 7. 存储设备管理

### 7.1 格式化

**低级格式化（物理格式化）**：

- 将磁盘划分为控制器可读写的扇区
- 每个扇区包含：头信息 + 数据（通常 512B）+ ECC

**逻辑格式化（创建文件系统）**：

- 在磁盘上建立文件系统数据结构
- 将磁盘划分为一组或多组柱面，每组柱面都视为逻辑磁盘
- 将块分组为**簇（Cluster）**：磁盘 I/O 以块为单位，文件 I/O 以簇为单位

### 7.2 分区与挂载

- **根分区**：包含操作系统，启动时挂载
- 其他分区可自动或手动挂载
- 挂载时检查文件系统一致性（元数据是否正确）
- **引导块（Boot Block）**：指向引导加载程序，用于加载内核

### 7.3 交换区管理

交换空间（Swap Space）用于内存不足时将进程/页面换出到磁盘：

- 辅助存储比 DRAM 慢，优化交换性能至关重要
- 可有多个交换空间，分散 I/O 负载
- 最好使用**专用设备**（原始分区），而非文件中的文件

### 7.4 坏块处理

- 磁盘控制器维护坏块列表，将坏扇区**重映射**到备用扇区
- **扇区备用**（Sector Sparing）：替换坏扇区为好扇区

## 8. 网络存储

### 8.1 NAS（网络附加存储）

- 通过**网络**（而非本地总线）提供存储
- 远程连接到**文件系统**
- 常用协议：**NFS**（Unix/Linux）、**CIFS**（Windows）
- 通过 TCP/UDP 在 IP 网络上传输

### 8.2 iSCSI

- 通过 IP 网络承载 **SCSI 协议**
- 远程连接到**块设备**（不是文件系统层面，是设备层面）

---

## 9. SAN（存储区域网络）

- 大型存储环境的标准方案
- 一个或多个存储阵列连接到光纤通道交换机或 InfiniBand 网络
- 多台主机也连接到交换机
- 通过 **LUN（逻辑单元号）** 将特定存储分配给特定服务器
- 优点：灵活，易于动态扩容、分配存储

```
存储阵列 ─┐
           ├─ SAN 交换机 ─── 主机1
存储阵列 ─┘               ─── 主机2
磁带库                      ─── 主机3
```

## 10. RAID

### 10.1 为什么需要 RAID？

HDD 的问题：

1. **可靠性**：机械部件会损坏，扇区可能悄无声息地损坏
2. **容量**：单盘容量有限，跨多盘管理麻烦
3. **性能**：单盘带宽受限

**RAID（Redundant Array of Independent Disks，独立冗余磁盘阵列）**：

- 用多个物理磁盘创建一个**更大、更快、更可靠**的逻辑磁盘
- 对外**透明**：软件看到的是一块大磁盘，不需要显式管理多个磁盘
- 内部由专用 CPU + RAM + 非易失性存储管理

### 10.2 RAID 核心技术

**条带化（Striping）**：将数据分散到多个磁盘的条带（Strip）上，并行读写，**提高性能**。

**镜像（Mirroring）**：将数据完整复制到另一组磁盘，**提高可靠性**。

**奇偶校验（Parity）**：用异或运算存储冗余信息，磁盘故障时可恢复数据，**用较少冗余提高可靠性**。

> [!tip] 奇偶校验原理 对 N 个磁盘对应位做 XOR，存到校验盘： `P = D1 ⊕ D2 ⊕ D3 ⊕ ... ⊕ Dn` 某磁盘 Di 故障时：`Di = P ⊕ D1 ⊕ ... ⊕ D(i-1) ⊕ D(i+1) ⊕ ... ⊕ Dn`

---

### 10.3 RAID 各级别详解

#### RAID 0 — 纯条带（非冗余）

```
磁盘1      磁盘2      磁盘3      磁盘4
strip 0   strip 1   strip 2   strip 3
strip 4   strip 5   strip 6   strip 7
...
```

- 数据按条带分布在所有磁盘上
- **无冗余**，不是"真正的 RAID"
- **读写性能最高**（N 块盘并行）
- **可靠性最低**：任一磁盘故障，所有数据丢失

**适用**：对性能要求极高、数据可丢失的场景（如视频剪辑临时存储）

---

#### RAID 1 — 镜像

```
磁盘1      磁盘2   |   磁盘3（镜像1）  磁盘4（镜像2）
strip 0   strip 1  |   strip 0        strip 1
```

- 所有数据**完全复制**一份
- 任一磁盘故障，数据仍可从镜像盘读取
- **没有写惩罚**（写入时同时写两盘，延迟不增加）
- 主要缺点：**成本翻倍**（需要 2N 块磁盘）
- 读性能可翻倍（两个副本可并行读），写性能与单盘相当

---

#### RAID 2 — 汉明码冗余

```
数据位: b0 b1 b2 b3 | 校验位: f0(b) f1(b) f2(b)
```

- 使用**汉明码（Hamming Code）**实现纠错
- 并行访问（所有磁盘同步读写）
- 需要 N+m 块磁盘（m 与 log N 成正比）
- 实际较少使用（被 RAID 3 取代）

---

#### RAID 3 — 位交错奇偶校验

```
数据盘: b0 | b1 | b2 | b3 | 校验盘: P(b)
```

- 以**位（bit）**为单位条带化
- 只需**1块冗余盘**，无论数据盘有多少
- 并行访问，数据传输速率极高
- 适合大块连续数据（如视频流）
- 不适合小随机 I/O（所有操作需所有磁盘参与）

---

#### RAID 4 — 块级奇偶校验

```
磁盘1    磁盘2    磁盘3    磁盘4  | 校验盘
block0  block1  block2  block3  | P(0-3)
block4  block5  block6  block7  | P(4-7)
```

- 以**块（Block）**为单位条带化（独立访问）
- 1块独立校验盘存储奇偶校验
- **写惩罚（Write Penalty）**：每次小写 I/O 需要先读旧数据和旧校验，计算新校验，再写（read-modify-write）
- 校验盘成为**写操作瓶颈**（每次写都要更新它）

> [!warning] RAID 4 的瓶颈 校验盘必须参与所有写操作，是系统性能的瓶颈。RAID 5 解决了这个问题。

---

#### RAID 5 — 块级分布奇偶校验 ⭐ 最常用

```
磁盘1     磁盘2     磁盘3     磁盘4     磁盘5
block0   block1   block2   block3   P(0-3)
block4   block5   block6   P(4-7)   block7
block8   block9   P(8-11)  block10  block11
block12  P(12-15) block13  block14  block15
P(16-19) block16  block17  block18  block19
```

- 与 RAID 4 类似，但**将奇偶校验分散到所有磁盘**
- 采用轮转（Round-Robin）方案
- **消除了写瓶颈**（校验不集中在一块盘）
- 任一磁盘故障不丢数据
- 是目前**最广泛使用**的 RAID 级别

**写惩罚仍存在**：每次写需读-改-写（4次 I/O：读旧数据、读旧校验、写新数据、写新校验）

---

#### RAID 6 — 双重分布奇偶校验

```
磁盘1    磁盘2    磁盘3    磁盘4    P        Q
block0  block1  block2  block3  P(0-3)  Q(0-3)
```

- 存储**两种不同的奇偶校验**（P 和 Q）到不同磁盘
- 可承受**同时故障两块磁盘**，数据不丢
- 数据可用性极高
- 代价：每次写需更新两个校验块，**写惩罚更大**
- 需要 N+2 块磁盘

---

### 10.4 RAID 级别对比

|级别|冗余方式|最少磁盘|可容忍故障|读性能|写性能|适用场景|
|---|---|---|---|---|---|---|
|RAID 0|无|2|0|最高|最高|高性能、不重要数据|
|RAID 1|镜像|2|1（或更多）|高|中|高可靠性、数据库日志|
|RAID 3|位级校验|3|1|极高（顺序）|极高（顺序）|大文件流媒体|
|RAID 5|分布块校验|3|1|高|中（有惩罚）|**通用，最常用**|
|RAID 6|双重分布校验|4|2|高|低（惩罚大）|高可靠性要求|

> [!warning] RAID 不是备份！ RAID 提供的是**高可用性（HA）**，防止磁盘故障导致数据不可访问。 RAID 不能防止：文件误删、勒索软件加密、火灾/洪水等灾难性损失。 **备份（Backup）才是真正的数据保护**。

---

### 10.5 扩展：ZFS

传统 RAID 只防磁盘故障，不能防止数据静默损坏（Silent Corruption）。

**ZFS（Zettabyte File System）** 的增强：

- 为**所有数据和元数据**添加校验和
- 校验和与指向对象的指针一起保存，可检测对象是否被篡改或损坏
- 能够检测并纠正数据和元数据损坏
- ZFS 还取消了传统卷/分区概念，改用**存储池（Storage Pool）**
    - 磁盘分配到池中，多个文件系统共享该池
    - 空间动态分配，类似 `malloc()`/`free()`

## 11. 例题精选

> [!example] 例题1：磁盘访问时间计算（基础+细节）
> 
> **题目**：某磁盘转速为 10000 RPM，平均寻道时间为 4ms，传输速率为 200MB/s，控制器开销可忽略不计。 (1) 计算平均旋转延迟 (2) 计算读取一个 8KB 数据块的平均 I/O 时间 (3) 如果连续读取 1000 个 8KB 数据块（分布在磁盘各处），总时间约为多少？
> 
> **解**： (1) 旋转一圈时间 = 60s / 10000 = 6ms 平均旋转延迟 = 6ms / 2 = **3ms**
> 
> (2) 数据传输时间 = 8KB / 200MB/s = 8×1024B / (200×10^6 B/s) ≈ **0.04ms** 平均 I/O 时间 = 4ms + 3ms + 0.04ms ≈ **7.04ms**
> 
> (3) 每次 I/O 约 7.04ms，1000 次 = **7.04 秒** 注意：如果这 1000 块是连续存放的，只需一次寻道+旋转，传输时间 = 1000 × 0.04ms = 40ms，约 **0.047秒**！ 这说明**顺序 I/O 比随机 I/O 快约 150 倍**，文件系统设计要尽量顺序存放。

---

> [!example] 例题2：磁盘调度算法计算（高频考点）
> 
> **题目**：磁盘有 300 个磁道（0-299），磁头当前在第 **150** 道，正在向**高磁道方向**移动。 请求队列（按到达顺序）：**86, 147, 91, 177, 94, 150, 130, 202, 55, 167**
> 
> 分别用 FIFO、SSTF、SCAN、C-SCAN 计算磁头移动总距离，并比较。
> 
> **解**：
> 
> **FIFO**（按到达顺序）： 150→86→147→91→177→94→150→130→202→55→167 距离：64+61+56+86+83+56+20+72+147+112 = **757 道**
> 
> **SSTF**（每次选最近的）： 从150开始，未服务队列：{86,147,91,177,94,150,130,202,55,167} 150→150(距0)→147(距3)→130(距17)→91(距39)→94(距3)→86(距8)→55(距31)→177(距122)→167(距10)→202(距35) 距离：0+3+17+39+3+8+31+122+10+35 = **268 道**
> 
> **SCAN**（向高磁道方向先走，到299再折返）： 150→167→177→202→**299**→147→130→94→91→86→55 距离：(299-150)+(299-55) = 149+244 = **393 道**
> 
> **C-SCAN**（向高磁道方向，到299后快速返回0，再向高方向）： 150→167→177→202→**299**→0→55→86→91→94→130→147 距离：(299-150)+(299-0)+(147-0) = 149+299+147 = **595 道**
> 
> |算法|总距离|排名|
> |---|---|---|
> |SSTF|268|1（最短）|
> |SCAN|393|2|
> |C-SCAN|595|3|
> |FIFO|757|4（最长）|
> 
> **结论**：SSTF 总距离最短，但可能有饥饿；SCAN 在效率和公平间平衡；C-SCAN 提供最均匀的等待时间。

> [!example] 例题3：RAID 奇偶校验计算
> 
> **题目**：RAID 5 有 4 块数据盘 + 1 块校验盘（共 5 块）。某条带的数据如下（8位）：
> 
> - D1 = 10110101
> - D2 = 01101100
> - D3 = 11001010
> - D4 = 00110011
> 
> (1) 计算奇偶校验值 P (2) 若 D2 盘故障，如何恢复 D2？ (3) 为什么 RAID 6 需要能承受 2 块盘同时故障？
> 
> **解**： (1) P = D1 ⊕ D2 ⊕ D3 ⊕ D4
> 
> ```
>   10110101
> ⊕ 01101100
> = 11011001
> ⊕ 11001010
> = 00010011
> ⊕ 00110011
> = 00100000
> ```
> 
> **P = 00100000**
> 
> (2) D2 = P ⊕ D1 ⊕ D3 ⊕ D4
> 
> ```
>   00100000
> ⊕ 10110101
> = 10010101
> ⊕ 11001010
> = 01011111
> ⊕ 00110011
> = 01101100
> ```
> 
> **D2 = 01101100** ✓（与原值一致）
> 
> (3) RAID 5 只有 1 个校验量，只能恢复 1 块故障盘。在大规模存储系统中，更换故障盘期间（rebuild过程）可能很长（数小时到数天），这段时间内如果再有 1 块盘故障，RAID 5 就会数据丢失。RAID 6 用 2 个校验量（P和Q），可同时承受 2 块盘故障，大幅提升了实际可靠性。

> [!example] 例题4：SSD 写放大分析
> 
> **题目**：某 SSD 的 Flash 块大小为 256KB，页大小为 4KB（每块 64 页）。当前有一个块（Block X）的状态如下：
> 
> - 第 1-10 页：有效数据
> - 第 11-20 页：已删除（invalid，但 OS 未发 TRIM）
> - 第 21-64 页：空闲
> 
> 现在需要写入 8 个 4KB 页（共 32KB）的新数据。 (1) 无需 GC 时，直接写入，实际物理写次数是多少？ (2) 若 Block X 已满（无空闲页），GC 时需要哪些步骤？物理读写各几次？ (3) 解释为什么 TRIM 命令能提高 SSD 性能。
> 
> **解**： (1) 直接写入空闲页：物理写 **8 次**（每页 1 次），写放大系数 = 1（理想情况）
> 
> (2) 若块已满，GC 步骤： - 读出 10 个有效页 → **10 次物理读** - 擦除整个 Block X → **1 次擦除**（以块为单位） - 把 10 个有效页写回 → **10 次物理写** - 写入 8 个新页 → **8 次物理写** - 合计：10 读 + 1 擦 + 18 写 - **写放大系数 = 18/8 = 2.25**（逻辑写 8 次，物理写 18 次）
> 
> (3) 有了 TRIM，OS 删除文件时通知 SSD 第 11-20 页无效： - GC 时只需读出有效的 10 页，无需读无效页 - 更重要的是：SSD 知道无效页不需要保留，可以直接擦除整块，**省去了对无效页的复制操作** - GC 效率提高，后台 GC 能更快清理空间，保持写入性能 - **本质：TRIM 让 SSD 的逻辑删除和物理删除同步，消除了"无效数据的无谓复制"**

> [!example] 例题5：综合分析题
> 
> **题目**：某数据中心需要设计存储系统，有以下需求： (A) 视频渲染农场：需要极高的顺序读写带宽，数据可在任务完成后丢弃 (B) 数据库服务器：需要高随机 IOPS，数据绝对不能丢失，预算充足 (C) 归档存储：需要大容量、低成本，偶尔访问，可接受少量数据冗余
> 
> 请为每个场景推荐合适的存储方案（包括 RAID 级别、HDD/SSD），并说明理由。
> 
> **解**：
> 
> **(A) 视频渲染农场**：
> 
> - 推荐：**RAID 0 + HDD（大容量高转速）或 RAID 0 SSD**
> - 理由：RAID 0 提供最高的读写带宽（所有盘并行），无冗余开销；数据可丢弃，无需冗余；顺序 I/O 模式适合 HDD
> 
> **(B) 数据库服务器**：
> 
> - 推荐：**RAID 10（RAID 1+0）或 RAID 5/6 + SSD（NVMe）**
> - 理由：数据库以随机 I/O 为主，SSD 的高 IOPS 关键；RAID 10 = 镜像+条带，读写性能高且高可靠性；若预算有限可用 RAID 5 SSD，但需注意写惩罚；绝不用 RAID 0（无冗余）
> 
> **(C) 归档存储**：
> 
> - 推荐：**RAID 6 + HDD（大容量低转速）**
> - 理由：HDD 每 GB 成本最低，适合大容量存储；RAID 6 双校验提供高可靠性，防止长期存储中的磁盘老化故障；偶尔访问对性能要求低，顺序读写已足够

## 12. 重点总结

> [!summary] 核心考点速览
> 
> **磁盘性能**：
> 
> - 访问时间 = 寻道时间 + 旋转延迟 + 传输时间
> - 寻道时间是最主要的瓶颈，磁盘调度主要优化它
> 
> **磁盘调度**（必考）：
> 
> - FIFO：最公平，效率最低
> - SSTF：效率高，可能饥饿
> - SCAN（电梯）：双向扫描，效率和公平间平衡
> - C-SCAN：单向扫描，等待时间最均匀
> - LOOK/C-LOOK：SCAN/C-SCAN 的优化版（不走到物理端点）
> 
> **RAID**（必考）：
> 
> - RAID 0：纯条带，无冗余，性能最高
> - RAID 1：镜像，冗余最简单，成本最高
> - RAID 5：分布奇偶校验，最常用，N+1 盘
> - RAID 6：双重奇偶校验，可承受 2 盘故障，N+2 盘
> 
> **SSD 关键概念**：
> 
> - 写放大：一次逻辑写触发多次物理操作
> - 磨损均衡：延长 SSD 寿命
> - TRIM：让 OS 通知 SSD 哪些页已失效
> - GC：SSD 内部的垃圾回收，维持写性能
> - NVMe 直连 PCIe，比 SATA 快得多
