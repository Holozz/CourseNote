# 前端总体设计架构

> AI 个性化私人健康管理系统 · 前端架构文档
> 版本 1.0

---

## 1. 项目概述

AI 个性化私人健康管理系统是一款面向个人用户的智能健康管理平台。前端基于 **Vue 3 + TypeScript + Vite** 构建，提供健康数据管理、AI 健康画像、个性化健康计划、健康知识推送、定时提醒等功能，并包含管理员后台模块。

---

## 2. 技术栈

| 类别 | 选型 | 版本 | 选型理由 |
|------|------|------|----------|
| 框架 | Vue 3 | 3.5.x | Composition API + `<script setup>`，生态成熟 |
| 语言 | TypeScript | 6.0 | 静态类型检查，减少运行时错误 |
| 构建工具 | Vite | 8.0 | 极速冷启动，原生 ESM |
| UI 组件库 | Element Plus | 2.14 | 企业级 Vue3 组件库，中文文档完善 |
| 路由 | Vue Router | 5.0 | 官方路由方案，支持懒加载 |
| 状态管理 | Pinia | 3.0 | Vue3 官方推荐，TypeScript 友好 |
| HTTP 客户端 | Axios | 1.16 | 拦截器机制，统一错误处理 |

### 6.3 路由守卫

```mermaid
flowchart TD
    START["导航触发"] --> CHECK{目标路径?}

    CHECK -->|"/login 或 /register"| HAS_TOKEN1{有 token?}
    HAS_TOKEN1 -->|是| REDIR_HOME["重定向 /home"]
    HAS_TOKEN1 -->|否| ALLOW1["放行 ✅"]

    CHECK -->|其他路径| HAS_TOKEN2{有 token?}
    HAS_TOKEN2 -->|否| REDIR_LOGIN["重定向 /login"]
    HAS_TOKEN2 -->|是| NEED_ADMIN{meta.requiresAdmin?}

    NEED_ADMIN -->|否| ALLOW2["放行 ✅"]
    NEED_ADMIN -->|是| IS_ADMIN{role === 'admin'?}
    IS_ADMIN -->|是| ALLOW3["放行 ✅"]
    IS_ADMIN -->|否| REDIR_HOME2["重定向 /home"]
```

**守卫逻辑：**
- 已登录用户访问登录/注册页 → 自动跳转首页
- 未登录用户访问业务页 → 自动跳转登录页
- 非管理员访问 `/admin/*` → 自动跳转首页
- 判断依据：`localStorage` 中的 `token` 和 `role`

## 7. 数据流设计

### 7.1 整体数据流

```mermaid
sequenceDiagram
    participant View as View 页面
    participant API as API 函数
    participant Axios as Axios 实例
    participant Inter as 拦截器
    participant Backend as 后端 API
    participant Store as Pinia Store
    participant LS as localStorage

    View->>API: 调用 api/xxx.ts 中的函数
    API->>Axios: 发送 HTTP 请求
    Axios->>Inter: 请求拦截器（自动附加 token）
    Inter->>Backend: Authorization: Bearer <token>
    Backend-->>Inter: 响应（ApiResponse<T>）
    Inter->>Inter: 响应拦截器（统一错误处理 / 401 跳转登录）
    Inter-->>API: 返回数据
    API-->>View: 返回类型化响应

    View->>Store: 写入跨页面共享状态
    Store->>LS: 持久化 token 和 userInfo
    LS-->>Store: 初始化时恢复状态
```

### 7.2 Mock 数据流

当环境变量 `VITE_MOCK_API=true` 时，API 层会返回本地模拟数据而不请求后端：

```mermaid
flowchart TD
    VIEW[View 调用 API] --> API_FN[API 函数]
    API_FN --> CHECK{isMockEnabled?}
    CHECK -->|true| MOCK[mock.ts 模拟数据]
    CHECK -->|false| AXIOS[Axios 真实请求]
    MOCK --> SIM_DELAY[模拟延迟 300-800ms]
    SIM_DELAY --> RETURN_MOCK[返回 ApiResponse 格式数据]
    AXIOS --> BACKEND[后端服务]
    BACKEND --> RETURN_REAL[返回真实数据]
```

**Mock 开关：**
- `VITE_MOCK_API=true` — 全局 Mock 开关（健康数据、提醒、知识库、管理后台）
- `VITE_MOCK_AUTH=true` — 独立控制登录/注册 Mock

### 7.3 状态管理数据流

```mermaid
graph TB
    subgraph "Pinia Store (userStore)"
        TOKEN["token: string"]
        USER_INFO["userInfo: User | null"]
        IS_LOGIN["isLoggedIn: computed"]
        IS_ADMIN["isAdmin: computed"]
    end

    subgraph "localStorage 持久化"
        LS_TOKEN["'token'"]
        LS_USER["'userInfo' (JSON)"]
    end

    subgraph "API 层"
        REQ_INT["请求拦截器<br/>读取 token 附加到 Header"]
    end

    TOKEN <-.->|"双向同步"| LS_TOKEN
    USER_INFO <-.->|"双向同步"| LS_USER
    LS_TOKEN -->|"自动读取"| REQ_INT
```

**设计决策：**
- token 和 userInfo 同时存储在 Pinia（响应式）和 localStorage（持久化）
- 路由守卫直接从 localStorage 读取（避免 Pinia 初始化时序问题）
- API 请求拦截器从 localStorage 读取 token 附加到 Authorization 头
- 登出时同时清除 Pinia 和 localStorage

## 8. 设计决策与权衡

### 8.1 为什么选择 Vue 3 Composition API + `<script setup>`

- 比 Options API 更简洁，逻辑复用更方便
- `<script setup>` 编译时优化，更小打包体积
- 与 TypeScript 配合更自然

### 8.2 为什么路由守卫用 localStorage 而不用 Pinia

- Pinia 在页面刷新后会丢失状态，localStorage 可以持久化
- 路由守卫在 Pinia 初始化之前就可能执行，直接读 localStorage 更可靠
- 保持守卫逻辑简单、无依赖

### 8.3 为什么引入 Mock 层

- 后端 API 开发与前端开发并行，Mock 允许前端独立开发调试
- Mock 函数返回格式与真实后端完全一致（`ApiResponse<T>`），切换零成本
- Mock 数据包含增删改操作的内存模拟，支持完整交互流程

### 8.4 为什么 Canvas 自绘趋势图

- Element Plus 不内置图表组件
- Canvas 自绘避免了引入 ECharts 等重型图表库（~800KB+）
- 项目中图表需求简单（折线图 + 柱状图），自绘代码 ~200 行即可满足
- 配合 ResizeObserver 实现响应式自适应

## 9. 构建与部署

### 开发环境

```bash
cd frontend
npm install
npm run dev        # http://127.0.0.1:5173
```

### 生产构建

```bash
npm run build      # 输出到 dist/
```

Vite 配置了代理：开发时 `/api` 请求代理到 `http://127.0.0.1:8080`，生产环境由 Nginx 等反向代理统一处理。

### 环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `VITE_HOST` | 开发服务器地址 | `127.0.0.1` |
| `VITE_PORT` | 开发服务器端口 | `5173` |
| `VITE_API_PROXY_TARGET` | API 代理目标 | `http://127.0.0.1:8080` |
| `VITE_MOCK_API` | 全局 Mock 开关 | `false` |
| `VITE_MOCK_AUTH` | 登录/注册 Mock 开关 | `false` |
